# Deployment runbook

Written for: whoever is putting this online, step by step.

Frontend to **Vercel**, API and database to **Render**. Both have free or
cheap tiers adequate for an academic demonstration.

> **Docker configuration in `docker/` is unverified.** Docker was not
> installed on the development machine, so the images were never built.
> Render builds from the Dockerfile, so budget time to debug the first
> build.

---

## Before you start

- [ ] Code pushed to GitHub
- [ ] CI green (`.github/workflows/ci.yml`)
- [ ] `make all` has run locally, so `ml/models/` holds trained artifacts
- [ ] A Vercel account and a Render account
- [ ] An Anthropic API key, if you want the live Copilot rather than the
      deterministic fallback

### Decide how model artifacts reach the server

`ml/models/` is gitignored, because `.pt` and `.joblib` files do not belong
in git. Pick one:

| Option | How | Trade-off |
|---|---|---|
| **Commit them** (simplest) | `git add -f ml/models/*.joblib ml/models/*.pt` | Repository grows by ~5 MB; fine at this size |
| Render disk | Attach a disk, upload once, mount at `/app/ml/models` | Cleaner, more setup |
| Object storage | Fetch at container start | Most work |

For a demonstration, commit them. Without artifacts the API still boots —
Insights and the model panels report `available: false`, and the rest of the
app works.

## 1. Database and API on Render

1. **New → Blueprint**, point it at the repository. Render reads
   `render.yaml` and proposes `wealthos-api` plus `wealthos-db`.
2. Set the two secrets it cannot generate:
   - `ANTHROPIC_API_KEY` — your key, or leave blank for the fallback
   - `CORS_ORIGINS` — leave blank for now; you need the Vercel URL first
3. Deploy. `JWT_SECRET_KEY` is generated by Render and never touches git.
4. Watch the build. The first one takes several minutes, mostly PyTorch.

Migrations run automatically: `docker-compose.yml` and the Render start
command both run `alembic upgrade head` before uvicorn, so a fresh database
comes up usable.

**Verify:**

```bash
curl https://wealthos-api.onrender.com/health
```

Expect `status: ok`, `database: connected`, and an asset count.

### Seed the market data

The database starts empty of prices. From a machine with the processed data:

```bash
DATABASE_URL="<render external connection string>" \
  .venv/bin/python -m ml.pipelines.p04_seed_database --reset
```

This writes 58 assets and ~232,000 price rows. Until it runs, `/health`
reports zero assets and every analytics page will say there is no history.

## 2. Frontend on Vercel

1. **Add New → Project**, import the repository.
2. Set **Root Directory** to `frontend`. Vercel detects Next.js.
3. Add one environment variable:

   | Name | Value |
   |---|---|
   | `NEXT_PUBLIC_API_BASE_URL` | `https://wealthos-api.onrender.com` |

   It is `NEXT_PUBLIC_`, so it is baked into the client bundle at build
   time. Changing it needs a redeploy, not just a restart.
4. Deploy.

---

## 3. Close the CORS loop

The API rejects browser calls from an origin it does not know, so this step
is required and easy to forget.

On Render, set `CORS_ORIGINS` to your Vercel URL
(`https://wealthos.vercel.app`) and redeploy.

## 4. Verify the deployment

Walk the demonstration path on the live site:

- [ ] `/health` returns ok with a non-zero asset count
- [ ] Register a new account
- [ ] Import `docs/sample-holdings.csv`
- [ ] Overview shows a value, allocation donut and health score
- [ ] Risk shows volatility, Sharpe, a drawdown chart and the correlation grid
- [ ] Create a goal; its forecast shows three scenarios
- [ ] Insights shows the health breakdown, cluster, anomalies and forecast
- [ ] Copilot answers "Why is my portfolio risky?" and reports figures verified
- [ ] `/api/v1/models/status` shows all three artifacts loaded

Or point the browser suite at the deployment:

```bash
cd frontend
E2E_BASE_URL=https://wealthos.vercel.app \
E2E_API_URL=https://wealthos-api.onrender.com \
  npx playwright test
```

## Local stack with Docker

```bash
cd docker

docker compose up --build
```

Web on `:3000`, API on `:8000`. Unverified — expect to debug.

## Troubleshooting

| Symptom | Cause | Fix |
|---|---|---|
| Pages load, every panel empty | Browser blocked by CORS | Set `CORS_ORIGINS` to the exact Vercel origin, redeploy |
| `/health` shows 0 assets | Prices never seeded | Run stage 04 against the production `DATABASE_URL` |
| Insights panels say unavailable | Artifacts not in the image | Commit `ml/models/` or mount a disk |
| Copilot answers but says fallback | No `ANTHROPIC_API_KEY` | Set it on Render; this is expected behaviour otherwise |
| Build fails on `libxgboost.dylib` / OpenMP | Missing OpenMP | `libgomp1` is already in the Dockerfile; locally, `brew install libomp` |
| First request after idle is slow | Render free tier sleeps | Expected; warm it before a demonstration |
| 401 on every call after a while | Token expired (24h default) | Sign in again, or raise `ACCESS_TOKEN_EXPIRE_MINUTES` |

## Before showing it to anyone

- [ ] `JWT_SECRET_KEY` is generated, not the placeholder
- [ ] `.env` is not committed (it is gitignored; confirm)
- [ ] `ENVIRONMENT=production` and `DEBUG` is off
- [ ] HTTPS everywhere — both platforms do this by default
- [ ] `CORS_ORIGINS` names your origin exactly, not `*`
- [ ] The academic-prototype disclaimer is visible — it is in the footer and
      on every Copilot response
